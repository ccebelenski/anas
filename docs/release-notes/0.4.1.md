# ANAS 0.4.1

ANAS 0.4.1 is a point release for cloud sync. A wrong SMB or FTP
credential was reported under the generic failure verdict, and an SMB
task path that cannot work was accepted at save time and failed only at
its first run. Nothing changes on upgrade.

## A wrong SMB or FTP credential tests as an authentication failure

The remote Test behind the Cloud Sync wizard answers a failed probe with a
verdict. A wrong password on an SMB remote or an FTP remote was reported
as the generic failure verdict, although the server had named the
credential problem. Both answers are now recognised, with the server's
own sentence shown, so a mistyped password reads the same way on every
backend that names it: as an authentication failure.

## An SMB task needs the share name in its path

Under an SMB remote, the first component of the remote-side path is the
share name, as in `share/folder`. The Test door probes the remote root,
so it cannot catch a path that leaves the share out. The task wizard
now shows that fact under the path field while an SMB remote is selected,
and saving a task with an empty path under an SMB remote is refused with
the share-name shape named, at create and at update.

## A wrong crypt password no longer tests as ok

A crypt remote encrypts the names of everything stored under it, and
rclone silently skips the names it cannot decrypt, reporting them only in
debug output. Testing a crypt remote with a wrong password therefore
succeeded while the data it held was already unreadable. The Test now
reads that output: when the names stored at the remote do not decrypt
under the given password, the verdict is an authentication failure that
names the remote and points at the password (and the second password, if
one was set). When nothing is stored yet, the test still answers
reachable, with a note that the password could not be checked against
existing data.

## A remote another remote wraps cannot be removed first

The wrapping backends — crypt, alias, union, chunker, compress and the
others whose configuration names another remote — keep working only while
that remote exists. Deleting a remote that another remote still named was
accepted and left the wrapper pointing at nothing; every later use of it
failed. The delete now refuses with the referencing remotes named, until
they are removed first.

## A cancelled run no longer sits in systemd's failed list

A cancelled backup or cloud run ends its systemd unit with the runner's
cancel exit, and the unit stayed in the `systemctl --failed` list until the
task's next run. ANAS now settles the unit's failed state once the run is
over, so nothing is left for the operator to clear by hand; the task row
keeps reading cancelled, as it always has.

## Kernel-named vdev members link to the Disks list

A vdev member added to a pool by its kernel device name was shown in the
Dashboard's telemetry under that name and did not cross-reference to the
Disks list. The name is now resolved to the disk's stable by-id identity, so
the row carries the same id the Disks view lists. A member whose device
cannot be resolved keeps the name ZFS printed.

## Install

```
tar xzf anas-0.4.1.tar.gz && cd anas-0.4.1 && ./install.sh
```

Re-run over an existing install to upgrade. Hard-reload the browser
afterwards.
