ANAS 0.4.1 is a point release for cloud sync remote testing. The wrong
credentials of two backends were reported under the generic failure
verdict, and an SMB task path that cannot work was accepted at save time
and only failed at its first real run.

## A wrong SMB or FTP credential tests as an authentication failure

The remote Test behind the Cloud Sync wizard answers a failed probe with a
verdict. A wrong password on an SMB remote or an FTP remote was reported
as the generic failure verdict, although the server had named the
credential problem. Both answers are now recognised, with the server's
own sentence shown, so a mistyped password reads the same way on every
backend that names it: as an authentication failure.

## An SMB task needs the share name in its path

Under an SMB remote, the first component of the remote-side path is the
share name — `share/folder`, not a bare subfolder — and the Test door
probes the remote root, which cannot catch the mistake. The task wizard
now shows that fact under the path field while an SMB remote is selected,
and saving a task with an empty path under an SMB remote is refused with
the share-name shape named, at create and at update.

## Install

```
tar xzf anas-0.4.1.tar.gz && cd anas-0.4.1 && ./install.sh
```

Re-run over an existing install to upgrade. Hard-reload the browser
afterwards.

## Known issues

- A cancelled backup or cloud run is listed as failed by
  `systemctl --failed` until the task's next run. ANAS shows it as
  cancelled.
- The run viewer shows per-file detail only while a run is in progress;
  a finished run keeps its summary in the task's recent runs.
- Google Drive, OneDrive, Dropbox, Box and pCloud need a token obtained on
  a machine with a browser (`rclone authorize "<backend>"`); the node
  itself cannot open the sign-in page.
- Telemetry shows a partition-backed vdev member added by its kernel name
  under that name; it does not link to the Disks list. Members added by
  their by-id path do.
