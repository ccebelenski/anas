ANAS 0.3.4 is a small follow-up to 0.3.3 for remote mounts.

## Server and share fields on a new mount

Creating or testing a CIFS mount took the server and share fields as
typed. A server entered as `//10.0.0.5` or `10.0.0.5/` failed at the
name-resolution step with the raw text. A share entered with a leading
slash, or left empty when Test connection was pressed, reached the
kernel as a malformed path, and the result was reported as
"Unreachable — no route to the server", which pointed at the network
when the problem was the typing.

Both fields are now normalised the same way in the dialog and in the
daemon: a scheme such as `smb://`, leading `//` or `\\`, and trailing
slashes are removed from the server; the share is its bare name, with
an inner path such as `share/sub` kept. An empty share is refused up
front with a sentence that says what is expected. A path the kernel
still rejects is reported as malformed, never as unreachable. Test
connection is disabled until both fields are filled, and a test without
credentials no longer waits on a password prompt.

NFS gets the same treatment: `host:/export` pasted into the server
field is split, and the export always carries exactly one leading slash.

## Credentials on a new CIFS mount

Credentials are optional: leave both fields empty and the mount is
requested as a guest, which a server that allows anonymous access
accepts and any other server refuses with an authentication error
rather than a hang. Filling only one of the two fields is refused in
the dialog. A request the daemon rejects now says which field is wrong.

## If you hit this on 0.3.2 or 0.3.3

Nothing was written to the node. Enter the server as a bare host name
or address and the share as its bare name, fill both before pressing
Test, and the mount is created normally.

## Install / upgrade

Untar on the PVE node and run `sudo ./install.sh` (re-running over an
existing install is the upgrade path).
