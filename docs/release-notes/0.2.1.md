Three fixes from the first field reports after 0.2.0.

## Configurable gateway port (#2)

`install.sh` now takes `--port N`. The gateway's loopback port (default 3000) is
reached only by pveproxy, so this exists to avoid a collision when something else
on the node already uses 3000. On a fresh install the installer auto-picks the
next free port if 3000 is taken. The value is written to `/etc/default/anas` and
preserved across upgrades. Per-node — cluster nodes need not agree.

## AHR expansion survives a daemon restart (#1)

An AHR pool expansion no longer shows "halted" after `anasd` restarts
mid-expansion (typically an ANAS upgrade). The mdadm reshape is kernel-owned and
never actually stops; on start ANAS re-attaches to the in-flight expansion and
carries it to completion when the array is healthy. Degraded, inactive, and
missing-disk cases still stop for manual review.

## AHR disks grouped by array in the Disks view (#3)

AHR member disks group under their array (`<pool> / <array>`), the same way ZFS
pool members group by pool/vdev, instead of falling under "Other".

## Install / upgrade

Untar on the PVE node and run `sudo ./install.sh` (re-running over an existing
install is the upgrade path). Pass `--port N` if 3000 is in use.
