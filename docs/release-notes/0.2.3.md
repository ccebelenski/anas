Two fixes: node identity on FQDN hostnames, and honest sync-finished
notifications.

## Node identity from PVE, not the OS hostname (#5)

On nodes whose hostname is fully qualified (e.g. `pve-atlas.internal.example`),
ANAS showed "not installed on this node" even though the services were running:
the gateway derived its identity from `os.hostname()`, which never matched the
short node name PVE uses, so it treated its own node as a peer.

The gateway now reads its identity from `/etc/pve/local` — PVE's own record of
the node name — at startup, with `ANAS_NODE_NAME` as an explicit override and
the short hostname as the fallback. The startup log names which source was
used. Cross-node forwards also carry a loop-guard marker now, so any future
identity mismatch fails as one clear `FORWARD_LOOP` error instead of a
self-forward loop through pveproxy.

## AHR notifications say what actually finished

mdadm reports every sync operation as "Rebuild", so the monthly scheduled
parity check arrived as alarming "RebuildFinished" notifications. The md event
hook now distinguishes them:

- A **check** (the scheduled scrub) is reported as routine — "no disk was
  rebuilt" — with its parity-mismatch count. Zero mismatches stays
  informational; a nonzero count escalates to a warning that recommends an
  ANAS Scrub to identify affected files.
- A **real rebuild** reports whether it was exact: if md recorded unreadable
  sectors on the surviving disks during the rebuild, the notification says so
  and recommends a Scrub; a clean rebuild says the data was reconstructed
  exactly.

Long checks run in daily windows, so one notification per window is expected;
the message now explains that.

## Install / upgrade

Untar on the PVE node and run `sudo ./install.sh` (re-running over an existing
install is the upgrade path).
