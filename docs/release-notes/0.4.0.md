# ANAS 0.4.0

ANAS 0.4.0 adds cloud sync, self-service on SMB shares, an SSD read cache
for AHR pools, and dataset management on pools that PVE also uses. Nothing
changes on upgrade until you use the new screens.

## Cloud sync

A new **Cloud Sync** menu copies or mirrors a path to any of rclone's
backends. (GitHub #57)

- **Remotes.** Add a remote by backend. The form shows the fields that
  backend needs: a token for Google Drive, OneDrive, Dropbox, Box and
  pCloud, with your own OAuth client optional under its own heading; keys,
  region and endpoint for S3; account and key for B2 and Azure Blob; host,
  user and password or key for SFTP, FTP, WebDAV and SMB. Other backends
  render rclone's own option list. Test checks the remote before you save.
  Passwords are stored obscured in `/etc/anas/rclone.conf` and never
  returned by the API. A token pasted with rclone's marker lines around
  it, or wrapped in quotes, is cleaned up before it is used.
- **Tasks.** Copy (never deletes at the destination) or sync (mirrors the
  source, deletions included), with excludes, a bandwidth limit, a
  schedule with the backup cadence widget, and notifications. Preview runs
  a dry run and names what would be transferred or deleted; a sync that
  would empty the destination says so in red. A ZFS dataset or an AHR pool
  is copied from a transient snapshot; a sync from an empty source is
  refused, and a source on a mount that is configured but not mounted is
  refused with the mount named.
- **Runs.** Run now shows live progress on the task row and the dashboard.
  View run opens a live window with overall progress, a throughput graph
  over the last five minutes, speed, ETA, elapsed time, the files in
  flight with their own progress, and the files just finished or failed.
  A run that stops moving shows a stalled label within fifteen seconds.
  Cancel run stops a run behind a confirmation that states how long it has
  been going and how far it got; files already copied stay at the
  destination. Run now is refused while a run is in progress.
- **Copy back.** The Remotes window footer carries the one rclone command
  that copies data back to the node.

Backup tasks gain the same Cancel run and the same refusal of Run now while
a run is in progress.

## Datasets on pools PVE uses

Datasets that sit outside PVE's storage footprint on a pool PVE also uses
can now be created, shared, snapshotted, replicated and backed up from
ANAS. PVE's own datasets, its guest volumes and the pool paths registered
in `storage.cfg` are shown but never selectable, and a name PVE would claim
is refused. The system pool cannot be destroyed, exported or re-pointed
from ANAS. (GitHub #61)

## Self-service on SMB shares

- **Previous Versions.** A share on a ZFS dataset or an AHR pool exposes
  its snapshots to Windows and macOS clients as previous versions of files
  and folders. Turn it on per share.
- **Recycle bin.** Deleted files land in a `#recycle` folder on the share
  instead of disappearing, with a purge age per share. (GitHub #62)
- **Time Machine target (beta).** A share can be offered to macOS as a Time
  Machine destination with a size cap. The destination is chosen manually
  on the Mac; ANAS does not advertise it on the network.

## AHR read cache

An SSD can be attached to an AHR pool as a read cache and detached again,
from the pool's toolbar. The cache is writethrough: losing the SSD loses no
data. When the SSD fails or is pulled, ANAS removes the cache within
seconds and reads continue from the pool; the pool view, the dashboard and
a notification say so. If the filesystem was forced read-only by the
failure, a Remount verb restores writes. A pool whose cache device is
missing at boot is repaired before it is mounted. (GitHub #63)

An AHR expansion whose plan adds no usable capacity is refused with the
reason, and can be run anyway after confirmation.

## Backup source guard

A backup whose archive path sits on a mount that is configured in
`/etc/fstab` but not mounted fails before anything is snapshotted, naming
the archive, the path and the mount. The wizard shows the same warning on
the archive row while the mount is down. An empty mountpoint is no longer
backed up as a good snapshot.

## Disks

SMART readings are refreshed every thirty minutes while someone is looking,
so a climbing reallocated-sector count shows within the hour. A disk in
standby is never woken for it; its last reading is shown with its age. ATA
disks show their reported power mode. The dashboard shows the daemon's
version.

## Share users

A share user whose Samba password entry was stored under a different
spelling of the name, an entry left behind by an earlier deletion, could
authenticate and still be refused as a guest. Creating the user or setting
the password now verifies the stored entry and replaces a mismatched one;
the Share Users list marks a mismatch and says how to repair it; deleting
a user removes the entry under its stored name. (GitHub #68)

## Fixes

- The ANAS gateway restarts with the daemon, so a daemon restart no longer
  leaves the UI answering 502.
- A snapshot or scrub schedule re-created under a previously used name no
  longer fires immediately.
- A backup or cloud run interrupted by a daemon restart now ends as failed
  with the reason, instead of staying "running" until the next reboot.

## Install

```
tar xzf anas-0.4.0.tar.gz && cd anas-0.4.0 && ./install.sh
```

Re-run over an existing install to upgrade. Hard-reload the browser
afterwards.

## Known issues

- A cancelled backup or cloud run is listed as failed by
  `systemctl --failed` until the task's next run. ANAS shows it as
  cancelled.
- The run viewer shows per-file detail only while a run is in progress;
  a finished run keeps its summary in the task's recent runs.
- Google Drive, OneDrive, Dropbox, Box and pCloud need a token obtained on
  a machine with a browser (`rclone authorize "<backend>"`); the node
  itself cannot open the sign-in page.
- Telemetry shows a partition-backed vdev member added by its kernel name
  under that name; it does not link to the Disks list. Members added by
  their by-id path do.
