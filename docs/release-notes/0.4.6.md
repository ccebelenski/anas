# ANAS 0.4.6

A point release with three reported items (GitHub #83, #84, #85), the fixes
from a review of the whole project, and a Security section every operator
of 0.4.5 or earlier should read.

## Shares on a node that boots from ZFS (GitHub #85)

On a node installed with ZFS as its root filesystem, creating a share on a
path that is not on a ZFS dataset (a Hybrid RAID pool, an ext4 or XFS
mount) was refused: the path was taken for a ZFS dataset because the root
pool sits above it. A path is now on a ZFS dataset only when the
filesystem that serves it is ZFS.

On the same nodes:

- Creating a share user no longer fails with a timeout. The check for a
  free user id walked the whole root filesystem.
- Every disk of the boot pool reads "System" on the Disks screen.

## Snapshot schedules run when you say (GitHub #83)

A snapshot schedule takes a time of day, a weekday for weekly schedules, a
day of the month for monthly ones, and a month and day for yearly ones.
The schedule dialog edits them and the grid shows them. A day the month
does not have (the 31st in April) runs on the month's last day.

Existing schedules keep running as before until edited.

## Recursive replication (GitHub #84)

A replication, one-shot or recurring, can take a dataset with everything
below it. Child datasets can be excluded by name. Each dataset is sent on
its own, in order. A run stops at the first dataset that fails and says
which one failed and which were already sent; nothing is rolled back, and
the next run continues each dataset from its own last common snapshot.

## Replication

- A peer or remote that did not answer is reported as such, with ssh's
  own error line. It was reported as a missing pool.
- A replication target that was written to since its last run is noticed
  before the next run fails on it, shown on the task, and raised as a
  Proxmox notification by a new daily check (`anas-replcheck.timer`). A
  run that sends sets its target read-only again; a run with nothing to
  send leaves a target you made writable as it is and keeps reporting it.
- Renaming or destroying a snapshot that a replication task depends on is
  refused, with the task named. Turning read-only off on a replica asks
  for confirmation and says what it does to the next run; it is not
  refused, because a failover needs it.
- Dataset and snapshot names with characters the shell would change reach
  the remote `zfs` as written.

## iSCSI

- A LUN whose image is being restored from a backup is not served until
  the restore has finished. An interrupted restore leaves a mark on the
  image or volume; the LUN stays unmapped and the iSCSI screen says why
  and how to clear it. The mark on an image file is an extended
  attribute, so the installer now installs the `attr` package when it is
  missing.
- Repair is offered only for a missing LUN it can put back. For each LUN
  it cannot, the screen, the warning and the refusal give the same
  reason. A LUN whose backstore is still live is mapped back when the
  backstore is the saved one (same path, same serial, same device).
- A LUN that is saved and missing from the running configuration keeps
  its volume or image from being destroyed or reused until it is put
  back.
- A target with more than one portal group is read in full, and ANAS
  changes only targets it created.
- A stored CHAP secret that could not be read is reported as not read.
  It was reported as not set, and an edit was then refused with a
  misleading message.
- Turning CHAP on in a way that would leave an initiator unable to log
  in is refused.
- Host firewall rules are read from where Proxmox VE keeps them.

## Cloud sync and backup

- A cloud sync that reads from a ZFS snapshot no longer deletes the
  destination's copy of datasets nested below the source. In the
  snapshot a nested dataset appears as an empty folder, and a sync took
  that for a deletion while the preview reported nothing to delete.
  Nested datasets are now left out of the run and the preview agrees.
- Saved cloud remote options that hold a secret come back masked.
- Editing a backup task no longer resets the fields the edit did not
  send (among them whether the task is enabled).

## Hybrid RAID

- Self-heal classifies each damaged block by what was found and every
  diagnostic says what to do next. A scrub whose result could not be
  established never reads as clean.
- A cache whose status could not be read shows as unknown.

## What the screens show when a read fails

Across pools, disks, datasets, snapshots, replication, backup, scrubs,
iSCSI, mounts and users: a value that could not be read is shown as
unknown, and a failed read is said. Before, several screens showed "none",
"healthy" or an empty list in that case.

## Remote mounts

A CIFS password written on the `/etc/fstab` line is moved into the
mount's root-only credentials file the next time the mount is edited and
saved. The same line in `/etc/fstab.bak` is cleaned, or the job prints
the command that cleans it. A password is never placed on a command
line.

## Installer

- The Proxmox web server is reloaded, never restarted, when the ANAS hook
  changes.
- A failed upgrade says that the node is unchanged, or names what the
  rollback could not put back.
- The `attr` package is installed when missing (see iSCSI).
- An install prefix that is not an ANAS install is never replaced or
  removed.

## Security

Two defects in released versions are fixed here. Upgrade.

- **Cloud sync, 0.4.5 and earlier.** An account holding only the
  read privilege (`Sys.Audit`) on the node could have a command run as
  root through the Test of a cloud remote that was not saved yet. Testing
  an unsaved remote and previewing an unsaved task now require
  `Sys.Modify`. Nodes where
  every account with `Sys.Audit` is already trusted as an administrator
  were not exposed.
- **Share permissions, 0.4.5 and earlier.** When an administrator applied
  permissions to a folder and everything below it, a share user with
  write access inside that folder could redirect the change to a file
  outside it. The recursive apply no longer follows a name that was
  swapped while it ran; such entries are skipped and counted in the
  result. This needs `perl`, which Proxmox VE installs.

Limits that remain, both needing a share user who rearranges folders at
the moment an administrator's job runs:

- A recursive permission apply over a tree that is being rearranged while
  it runs can leave entries unchanged. The result says so when the walk
  saw the change; a file moved into a folder the walk had already
  finished is not seen at all. Applying again covers both.
- The automatic choice of a new user or group id skips ids that an ACL
  entry still names. A share user can hide such an entry from that check,
  and the id may then be handed out. The check writes nothing; giving the
  id yourself avoids it.

## Install

```
tar xzf anas-0.4.6.tar.gz && cd anas-0.4.6 && ./install.sh
```

Re-run over an existing install to upgrade. The installer reloads the
Proxmox web server when its hook changed. Hard-reload the browser
afterwards.
