One fix. Recommended for anyone running AHR expansions.

## AHR expansion: capacity is now always delivered (#4)

Resuming an expansion while the mdadm reshape was still running — including the
automatic re-attach 0.2.1 performs after a daemon restart or upgrade — could
report the expansion complete immediately and stop tracking it. The reshape
itself always finished safely at the kernel level, but the LVM and filesystem
grow steps never ran afterward: the array reached its new size while the pool's
usable capacity stayed at the old size.

ANAS now never reports an expansion complete while a reshape is in flight: it
waits out the reshape (with live progress), runs the grow steps after the kernel
publishes the new size, and reports the measured — not planned — capacity.

**If you already hit this** (all member disks present but usable capacity never
grew after an expansion), complete it by hand once the reshape has finished:

```sh
pvresize /dev/<md-device>
lvextend -l +100%FREE <pool>/<pool>-vol
btrfs filesystem resize max <mountpoint>
```

## Install / upgrade

Untar on the PVE node and run `sudo ./install.sh` (re-running over an existing
install is the upgrade path).
