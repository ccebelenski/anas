# ANAS 0.4.2

ANAS 0.4.2 is a point release for the Datasets view and snapshot
schedules. The pool-space chart grew past the page on a pool that also
holds Proxmox guest volumes, and a recursive snapshot schedule had no way
to leave a child dataset out. Nothing changes on upgrade.

## The pool-space chart keeps its height

The Datasets view opens with a chart of how the pool's used space breaks
down across its top-level datasets. On a pool that is also Proxmox
storage, every guest disk image is a top-level dataset, and the chart's
legend listed each one. With enough guests the chart filled the page and
the dataset tree beneath it had no room left, with nothing to scroll.

Everything Proxmox owns on the pool, guest volumes and any registered
storage, is now one segment labelled Proxmox storage, the way the Name
column already sets it apart. The legend shows the
six largest datasets by name and folds the rest into one row whose
tooltip lists them. The chart's height is fixed whatever the pool holds,
and the tree keeps the rest of the page.

## A recursive schedule can leave datasets out

A snapshot schedule with Include child datasets ticked snapshots the whole
tree under its target. An hourly schedule on a pool therefore took hourly
snapshots of every dataset under it, including the media library or the
backup target that only needs a daily one, and the alternative was one
schedule per dataset.

The schedule dialog now offers Exclude datasets once Include child
datasets is ticked, listing the target's children. An excluded dataset
and everything under it are left out of every run. The remaining
snapshots are still taken in one ZFS call, so they are as consistent with
each other as a plain recursive snapshot. A Proxmox guest volume under
the target can be excluded the same way, which lets a pool carrying both
ANAS datasets and guest storage have one recursive schedule. Existing
schedules are untouched.

## Retention now reaches every dataset a recursive schedule snapshots

A schedule with Include child datasets ticked took snapshots across the
whole tree under its target, but its retention policy was applied to the
target alone. Every child dataset kept every snapshot the schedule had ever
taken, and the space they held only grew.

Retention is now applied to each dataset the schedule covers, one snapshot
at a time, and a held snapshot on a child is skipped and reported exactly
as one on the target is. The first run after upgrading brings every child
down to the policy, so nothing has to be cleaned up by hand. A child that
also has a schedule of its own keeps whichever count is more generous.
Snapshots the schedule left on a dataset that has since been excluded are
removed as well, unless another schedule covers that dataset, and
snapshots that arrived by replication are never touched. The run's log,
its notification and the schedule's detail now list what was pruned per
dataset.

## Install

```
tar xzf anas-0.4.2.tar.gz && cd anas-0.4.2 && ./install.sh
```

Re-run over an existing install to upgrade. Hard-reload the browser
afterwards.
