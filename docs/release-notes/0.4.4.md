# ANAS 0.4.4

A hardening release: no new workflows, fixes and guards across the
shipped features.

## Reading and changing follow your Proxmox privileges

Proxmox decides who may use ANAS. A user with `Sys.Audit` on `/` can open
every ANAS view and read everything; changing anything, including a
mutation sent straight to the API, needs `Sys.Modify` on `/`, and a user
with it can change anything ANAS manages. Users without `Sys.Audit` see a
panel saying which privilege they lack instead of an empty or broken view.
A disabled Proxmox user, an expired session
and a request that did not come through the Proxmox web server are
refused the same way Proxmox refuses them elsewhere; API tokens are not
accepted.

## Nothing is left half done

Every operation checks everything it needs before it starts, and checks
again when its turn comes, so a change that happens while it waits in the
queue refuses the operation instead of running on stale facts:

- Destroying, rolling back, renaming or reconfiguring a dataset, pool,
  Hybrid RAID pool, mount, iSCSI target, share, user, task or schedule
  re-reads its target first. If the target changed since the confirmation
  was shown, the operation is refused and the confirmation names what
  changed.
- A forced rollback or a recursive dataset destroy that would reach a
  snapshot something holds (a replication base, for example) is refused
  before anything runs, naming the snapshot and who holds it. Previously
  ZFS destroyed the unheld snapshots first and then failed on the held one.
- Deleting a backup, cloud sync or replication task, or a snapshot
  schedule, while its run is active is refused; the message names the run
  and how to cancel it.
- A data mover (a replication send, a backup or cloud run, a snapshot
  schedule firing) holds its source for the run: a destroy, rollback or
  rename of that source accepted meanwhile waits for the run to finish and
  is checked again afterwards, instead of killing the transfer midway.
  Deleting an unrelated snapshot no longer waits behind a long send.
- Unmounting, disabling or removing a mount something still uses lists the
  processes holding it; the confirmation binds that list, so a holder that
  appears later is refused rather than forced.
- Exporting or destroying a pool names every share, export, task, mount
  and schedule that still refers to it.
- A pool is treated as a system pool by what is mounted from it, never by
  its name. Attaching, replacing and expanding on a system pool are
  allowed again; export, destroy and changing its mountpoint stay refused.

## Partitions and ownership

- A partition can again be the new device of an attach, replace or
  expansion. Creating a pool or adding a vdev still takes whole disks.
- A recursive permission change on a dataset or share also changed
  ownership and permissions inside other filesystems mounted below it (an
  NFS or CIFS mount, another pool's dataset). It now stops at every mount
  it was not asked to change and lists them in the confirmation. If you
  applied a recursive permission change in 0.4.3 to a tree with such a
  mount below it, check that mount's ownership.
- A dataset, snapshot, permission or share operation on something Proxmox
  owns is refused with the same answer everywhere; a storage configuration
  that cannot be read says so instead.

## Users and groups

- Creating a user or group always passes an explicit id. ANAS picks the
  next free id in its range that owns no files on any managed dataset or
  share folder, or you can set the id yourself under Advanced; an id another
  account already has is refused. An explicit primary group can be chosen
  on Add.
- When a user id equals an existing group's id, or a group id equals an
  existing user's id, the dialog asks for confirmation and says how to
  avoid it.
- Deleting a user whose private group would go with it says so in the
  confirmation, and refuses when a share still names that group or another
  account uses it as its primary group. The accounts reserved for the
  system cannot be changed through ANAS.
- The supplementary and primary group lists offer only groups ANAS can
  assign.

## Long reads can be cancelled

The cloud sync preview, the remote test and the backup catalog listing no
longer stop after a few seconds. Each runs as a job with a generous time
limit, shows progress where there is any, and has a Cancel button.

## Hybrid RAID

- Destroying a pool with two or more bands, or one grown by an expansion,
  failed partway with "Failed to find logical volume" after the pool had
  been unmounted, and a second Destroy was needed to finish. Destroy now
  removes these pools completely in one job.
- The disk cleanup after a destroy wipes exactly what the confirmation
  listed and leaves a cache or spare that shares a disk alone, saying so.
- When the array tooling cannot be read, the Hybrid RAID view says so
  instead of showing no pools, and a backup of a pool it could not confirm
  says which lock it does not hold.
- Detaching a read cache could leave the SSD listed as Unknown when
  something was using the disk at the moment its slice was deleted, with no
  message. The detach now removes the slice from the running system directly
  in that case and still hands the disk back; it fails naming the disk, and
  the command that clears it, only when that is refused too.

## Secrets stay out of replies

A backend that echoes a password or token in an error line (a wrong
credential answered with the value, a URL repeated back) no longer puts
it into a job's result, a notification, a progress line or the restore
marker. Every such line shows `[secret]` in its place.

## Other fixes

- Replication remote settings cannot carry ssh options; mount entries with
  spaces or special characters are written and read correctly; share,
  export and rclone values that would break their file are refused.
- A save the daemon refused shows the refusal; a reload that fails
  afterwards no longer replaces it.
- A created cloud task appears and is selected in the list straight away.
- A job is followed to its real end: a still-running job says so, a lost
  one is reported, and the result is applied when it arrives.
- Scrub and run-now actions no longer wait behind their own supervisor.
- Disabling a mount writes `noauto` and keeps the line; Remove takes it
  out. An automount entry is neutralised by Disable and Remove.
- The web UI's actions send Proxmox's CSRF token; the daemon accepts JSON
  bodies only.

## Install

```
tar xzf anas-0.4.4.tar.gz && cd anas-0.4.4 && ./install.sh
```

Re-run over an existing install to upgrade. The installer reloads the
Proxmox web server when its hook changed. Hard-reload the browser
afterwards.
