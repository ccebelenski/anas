# Users and groups

## Users & Groups (filtered to relevant accounts)

| Method | Path | Description | Response |
|--------|------|-------------|----------|
| `GET` | `/v1/identity/users` | List users (UID >= UID_MIN, no service accounts) | `200` |
| `POST` | `/v1/identity/users` | Create a user (`useradd -N`, always with an explicit `-u`). Optional `uid` (the share band [1000, 60000]): used as given, refused only when an account already holds it, never checked for files; absent, ANAS picks the next id above the highest in-band account that owns nothing on any ZFS filesystem or under a non-ZFS share or export root (a root that does not exist owns nothing; one that cannot be read refuses `409 id-check-unreadable`) (cr.29). The pick also passes over an id that a POSIX ACL entry names on a folder under a share or export path, a mounted ZFS filesystem with POSIX ACLs on that PVE does not own, or a mounted AHR pool (folders only; cr.59, cr.59n, cr3.nodefix); a user with write access to a folder inside one of those trees can hide such an entry from the check by swapping a parent folder for a symbolic link while it reads, and the pick may then hand out that id (the check writes nothing, and file ownership is still read). Optional `primaryGroup`: an existing group in the band, or the default `users` (gid 100), passed as `-g <gid>`; absent, the default (cr.29c). A uid N whose gid N belongs to an unrelated group (or the reverse) is a bound `409` confirm (cr.29c) | `202`/`409` with job |
| `GET` | `/v1/identity/users/:name` | User detail | `200` |
| `PUT` | `/v1/identity/users/:name` | Modify a user | `202` with job |
| `POST` | `/v1/identity/users/:name/smb-password` | Set/update SMB password | `202` with job |
| `DELETE` | `/v1/identity/users/:name` | Remove a LOCAL share user (confirm-gated; a hard `409` when any share's user-list parameter names it — `valid users`, `invalid users`, `read list`, `write list`, `admin users`, `force user`, `@`/`+`/`&` group forms included — or when it is directory-provided or a system account — an out-of-band uid or a Proxmox VE @pam login, nothing else (identity.5, GitHub #78): group membership is not a criterion, so a hand-made admin login (`adduser chris; usermod -aG sudo chris`) is a share user ANAS lists, can disable (reversible from root@pam's shell) and deletes only with the confirm code, and a share group named `admin` or `wheel` is a share group). ACL entries are not read: no ACL reference is reported or refused (cr.29 reads file ownership for the create's pick, not ACLs). `userdel` without `-r` or `-f`: its files keep their uid, said once in the confirm; the SMB passdb entry is removed if present. With `USERGROUPS_ENAB yes` userdel also removes the group named like the user when it is the user's primary group with no other member and no other account's primary group, and userdel has no option to keep it: the confirm names that group, binds it, and the delete refuses as the group delete would (`referenced-by-share`, `SYSTEM_ACCOUNT`) (cr.29d) | `202`/`409` with job |
| `GET` | `/v1/identity/groups` | List groups: root, the default primary group (`users`, gid 100; GitHub #78, identity.4) and the share band [1000, 60000] — root is listed, never mutable; `users` is listed, its membership editable, never deleted (`isListedGroup`, `isJoinableGroup`; identity.5) | `200` |
| `POST` | `/v1/identity/groups` | Create a group (always with an explicit `-g`). Optional `gid`: used as given, refused only when a group already holds it; absent, picked like a user's uid (cr.29). A gid N equal to an unrelated user's uid N is a bound `409` confirm (cr.29c) | `202`/`409` with job |
| `PUT` | `/v1/identity/groups/:name/members` | Modify a group (members) | `202` with job |
| `DELETE` | `/v1/identity/groups/:name` | Remove a LOCAL group (confirm-gated; hard `409`s: `primary-group-in-use` when it is an account's primary group, `referenced-by-share` when any share's user-list parameter names it, and `SYSTEM_ACCOUNT` for a system gid). ACL entries are not read: no ACL reference is reported or refused. The confirm says once that the files keep the gid | `202`/`409` with job |
