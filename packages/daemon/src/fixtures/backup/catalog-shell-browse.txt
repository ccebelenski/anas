############ 4. ARGUMENT QUOTING - what the shell accepts ############
--- unquoted space: SPLIT into two arguments (the trap) ---
### $ printf 'ls /with space.txt\nexit\n' | proxmox-backup-client catalog shell 'host/gtrestore/2026-08-25T19:16:45Z' data.pxar --ns $NS
Starting interactive shell    
Error: got additional arguments: ["space.txt"]
Usage:  ls [<path>]

 <path>     <string>
             target path.
### exit=0

--- double quotes / single quotes / unquoted BACKSLASH-escape: all work ---
### $ printf 'ls "/with space.txt"\nexit\n' | proxmox-backup-client catalog shell 'host/gtrestore/2026-08-25T19:16:45Z' data.pxar --ns $NS
Starting interactive shell    
with space.txt
### exit=0

### $ printf 'ls '/with space.txt'\nexit\n' | proxmox-backup-client catalog shell 'host/gtrestore/2026-08-25T19:16:45Z' data.pxar --ns $NS
Starting interactive shell    
with space.txt
### exit=0

### $ printf 'ls /with\\ space.txt\nexit\n' | proxmox-backup-client catalog shell 'host/gtrestore/2026-08-25T19:16:45Z' data.pxar --ns $NS
Starting interactive shell    
with space.txt
### exit=0

--- a backslash INSIDE double quotes is LITERAL (quoting cannot be rescued) ---
### $ printf 'ls "/with\\ space.txt"\nexit\n' | proxmox-backup-client catalog shell 'host/gtrestore/2026-08-25T19:16:45Z' data.pxar --ns $NS
Starting interactive shell    
Error: no such file or directory: "with\\ space.txt"
### exit=0

--- * and [ ] are NEVER globbed; backslash-escaping them is safe ---
### $ printf 'ls /star\\*name.txt\nls /bracket\\[1\\].txt\nls /mix\\ \\[a\\]\\ \\*\\ b.txt\nexit\n' | proxmox-backup-client catalog shell 'host/gtrestore/2026-08-25T19:16:45Z' data.pxar --ns $NS
Starting interactive shell    
star*name.txt
bracket[1].txt
mix [a] * b.txt
### exit=0

--- a double quote inside a single-quoted argument survives ---
### $ printf 'ls '/with"space.txt'\nls /docs\nexit\n' | proxmox-backup-client catalog shell 'host/gtrestore/2026-08-25T19:16:45Z' data.pxar --ns $NS
Starting interactive shell

notes.txt
readme.md
### exit=0
